# فروشگاه اینترنتی مسلم بیوتی | MOSLEM BEAUTY

این پروژه یک فروشگاه React/Vite متصل به Supabase است. کد فرانت‌اند، پنل مدیریت، SQL دیتابیس و سیاست‌های دسترسی در همین بسته قرار دارند.

## وضعیت واقعی این بسته

- رابط فروشگاه فارسی، راست‌چین و واکنش‌گرا پیاده‌سازی شده است.
- پنج محصول اولیه در نسخه نمایشی داخل برنامه وجود دارند تا پیش از اتصال دیتابیس هم ظاهر فروشگاه دیده شود.
- با اتصال Supabase، محصولات از دیتابیس خوانده می‌شوند و تغییرات پنل مدیریت بدون انتشار مجدد سایت در فروشگاه عمومی ظاهر می‌شوند.
- پنل ورود مدیر با Supabase Auth پیاده‌سازی شده است؛ کنترل دسترسی CRUD و آپلود تصویر در سمت دیتابیس با RLS انجام می‌شود.
- سفارش واتساپی، لینک اینستاگرام، تلفن و نشانی در رابط قرار داده شده‌اند.
- **هیچ پروژه Supabase یا حساب مالک از طرف شما ایجاد نشده و هیچ دامنه‌ای منتشر نشده است.** تا زمان انجام مراحل اتصال، نسخه آنلاین و پنل واقعی فعال نیستند.

## پیش‌نیازها

1. Node.js نسخه 20 یا جدیدتر
2. یک حساب Supabase
3. یک میزبان استاتیک سازگار با Vite (مانند Netlify، Vercel یا هاست دارای پشتیبانی از SPA)

## مرحله ۱: ساخت پروژه Supabase

1. وارد https://supabase.com شوید و یک پروژه جدید بسازید.
2. رمز دیتابیس را در جای امن نگه دارید.
3. از بخش **Project Settings → API** مقدار Project URL و کلید `anon` یا `publishable` را بردارید.
4. در **Authentication → Providers → Email** ورود با ایمیل را فعال نگه دارید.
5. در بخش **Authentication → Settings** گزینه ثبت‌نام عمومی (Allow new users to sign up) را خاموش کنید. فقط مالک را به‌صورت دستی ایجاد کنید.

## مرحله ۲: ساخت کاربر مالک به‌شکل امن

1. در Supabase به **Authentication → Users** بروید.
2. گزینه Add user را بزنید و ایمیل خودتان را وارد کنید.
3. یک رمز عبور قوی و اختصاصی تعیین کنید؛ آن را در فایل‌های پروژه یا پیام‌رسان قرار ندهید.
4. کاربر را ایجاد کنید و UUID کاربر را از فهرست کاربران کپی کنید.
5. در SQL Editor فایل `supabase/schema.sql` را اجرا کنید. این فایل جدول محصولات، سیاست‌های RLS، فضای تصاویر و پنج محصول اولیه را می‌سازد.
6. پس از اجرای فایل، در SQL Editor دستور زیر را با UUID واقعی کاربر خود اجرا کنید:

```sql
insert into public.store_admins (user_id)
values ('UUID-کاربر-مالک')
on conflict (user_id) do nothing;
```

**این مرحله تعیین‌کننده دسترسی مالک است.** تا وقتی UUID مالک در جدول `store_admins` ثبت نشده باشد، حتی کاربر Auth نیز اجازه افزودن/ویرایش/حذف محصول یا آپلود تصویر نخواهد داشت.

برای حذف دسترسی یک مدیر، رکورد مربوطه را از `public.store_admins` حذف کنید. برای این فروشگاه فقط یک مالک تعریف کنید و ثبت‌نام عمومی را خاموش نگه دارید.

## مرحله ۳: اتصال سایت به Supabase

1. فایل `.env.example` را به `.env` تغییر نام دهید.
2. مقادیر زیر را در آن جایگزین کنید:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
```

3. فقط URL و کلید عمومی anon/publishable را وارد کنید. **هرگز `service_role` یا کلید secret را در متغیرهای `VITE_` یا کد مرورگر قرار ندهید.**
4. بعد از تغییر `.env` سرور توسعه را دوباره اجرا کنید.

## مرحله ۴: اجرای محلی و ساخت نسخه انتشار

در ترمینال، داخل پوشه پروژه:

```bash
npm install
npm run dev
```

آدرس محلی که Vite اعلام می‌کند را باز کنید. برای ساخت خروجی نهایی:

```bash
npm run build
```

فایل‌های قابل انتشار داخل پوشه `dist` ساخته می‌شوند. برای بررسی نسخه نهایی:

```bash
npm run preview
```

## مرحله ۵: انتشار روی هاست

### Vercel یا Netlify
- مخزن Git را متصل کنید یا پوشه پروژه را بارگذاری کنید.
- Build command: `npm run build`
- Publish/Output directory: `dist`
- در Environment Variables دو متغیر `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` را ثبت کنید.
- بعد از ثبت متغیرها، یک Deploy مجدد انجام دهید.

### هاست معمولی
- ابتدا روی سیستم خود `npm run build` اجرا کنید.
- محتویات پوشه `dist` را در ریشه سایت (مثلاً `public_html`) بارگذاری کنید.
- برای مسیرهای SPA، همه مسیرهای ناشناخته باید به `index.html` بازنویسی شوند. در حال حاضر مسیر پنل با پنجره مدیریت داخل همان صفحه باز می‌شود و به مسیر جداگانه نیاز ندارد.

## مرحله ۶: استفاده از پنل

1. سایت را باز کنید و دکمه «مدیریت» را بزنید.
2. با ایمیل و رمز کاربر مالک که در Supabase ساخته‌اید وارد شوید.
3. نام، توضیحات، دسته‌بندی، قیمت، قیمت تخفیف‌دار، موجودی و تصویر را وارد کنید.
4. با ثبت محصول، داده در جدول `products` ذخیره می‌شود.
5. محصول فعال بلافاصله در فروشگاه عمومی و دسته‌بندی خودش دیده می‌شود. لازم نیست سایت را دوباره Deploy کنید.
6. برای مخفی‌کردن محصول، تیک «نمایش محصول در فروشگاه» را بردارید. برای حذف کامل، از دکمه حذف استفاده کنید.

## امنیت و محدودیت‌ها

- کلید عمومی Supabase در مرورگر قابل مشاهده است و این طبیعی است؛ امنیت با RLS و تابع `is_store_admin()` اعمال می‌شود.
- کلید `service_role` نباید هرگز در فرانت‌اند قرار گیرد.
- دسترسی نوشتن به محصولات و آپلود تصاویر فقط برای UUID ثبت‌شده در `store_admins` است.
- خواندن محصولات فعال عمومی است؛ خواندن محصولات غیرفعال فقط برای مدیر مجاز است.
- فایل تصویر حداکثر ۵ مگابایت و فرمت‌های JPG/PNG/WebP پذیرفته می‌شوند.
- URL تصاویر عمومی است تا مشتری بتواند عکس محصول را ببیند؛ عملیات آپلود، ویرایش و حذف فایل به مدیر محدود شده است.
- حذف محصول، فایل تصویر قدیمی را خودکار پاک نمی‌کند؛ در صورت نیاز فایل‌های بلااستفاده را از Storage پاک کنید.
- ورود مدیر به سیاست محدودسازی تلاش ناموفق (rate limit) و MFA وابسته به تنظیمات پروژه Supabase است؛ برای امنیت بیشتر MFA را در Supabase فعال کنید.
- این نسخه سفارش را به واتساپ منتقل می‌کند و پرداخت آنلاین، سبد خرید، ثبت سفارش داخل دیتابیس، پیامک و محاسبه هزینه ارسال ندارد؛ مطابق درخواست فعلی درگاه پرداخت اضافه نشده است.
- پیش از استفاده تجاری، تنظیمات حریم خصوصی، قوانین فروش، مرجوعی، مالیات و شرایط ارسال را با اطلاعات واقعی فروشگاه تکمیل کنید.

## عیب‌یابی کوتاه

- اگر پیام تنظیم Supabase دیدید، فایل `.env` یا متغیرهای محیطی هاست کامل نیستند.
- اگر ورود انجام می‌شود ولی ذخیره محصول خطای permission می‌دهد، UUID حساب واردشده را در `store_admins` بررسی کنید.
- اگر عکس بارگذاری نمی‌شود، اجرای `schema.sql` و وجود bucket با نام `product-images` و سیاست‌های Storage را بررسی کنید.
- اگر پس از تغییر متغیر محیطی هنوز اتصال برقرار نیست، برنامه را مجدداً build و deploy کنید.
